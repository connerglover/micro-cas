# T1.2: Polynomials (notes)

Files: `src/poly.py`, `src/polyb.py`, `src/polyc.py` (the CVPOLY family, parts A, B and C),
`tests/test_poly.py`. 46 tests, all passing in default and `--strict-depth` modes (one is `slow`).

## What was built

The family has **no imports at all**: no node, no run, and no calls between the parts. Each part
is a self-contained compile unit, so the tests need nothing but the three files. The coefficients
are Python ints only, and the code runs on the device subset (lint and FRAMELINT clean).

**Representations.**

- **Dense Z[x]** (`poly`, `polyb`): a list of ints, low degree first. `p[i]` is the coefficient of
  `x^i`. There are no trailing zeros; `[]` is 0 and `deg p = len(p) - 1`.
- **Sparse Z[x1..xn]** (`polyc`): a dict `{exponent tuple: nonzero int}`. Every key has n ints
  that are 0 or more; `{}` is 0. No result depends on dict order (`#@unordered-ok` loops only
  build dicts, sums or a `max`).
- Inputs are never mutated, and every output is normalized. Both properties are tested.

**Public API as implemented.** "Level" is the `#@L` level, so a caller must sit at a lower level.

| part | function | L | contract |
|---|---|---|---|
| poly | `padd(a, b, k=1)` | 7 | `a + k*b`. `padd([], a, c)` scales `a` by `c`. |
| | `pmul(a, b)` | 7 | product |
| | `ppow(a, n)` | 6 | `a^n` for `n >= 0` (`0^0 = 1`) |
| | `pderiv(a)` | 7 | derivative |
| | `peval(a, x)` | 7 | Horner; `x` may be an int, a float or a complex |
| | `pcont(a)` | 7 | content, `>= 0` (0 for `[]`) |
| | `pprim(a)` | 6 | primitive part with a positive leading coefficient |
| | `pdivrem(a, b)` | 6 | `(q, r, m)`: `m*a = q*b + r`, `deg r < deg b`, `m > 0`, `gcd(m, cont q, cont r) = 1`. So `q/m` and `r/m` are the quotient and remainder over Q, and `m` is minimal. `b != []`. |
| | `pdivex(a, b)` | 7 | the exact quotient in Z[x], or `None`; it stops at the first non-divisible coefficient. `b != []`. |
| | `pgcd(a, b)` | 5 | gcd in Z[x]: the gcd of the contents times the primitive-PRS gcd, `lc > 0`. `pgcd([], []) = []`. |
| | `yun(a)` | 4 | `(c, [(f, m), ...])` with `a = c * prod f^m`. Each `f` is primitive, square-free, of degree >= 1, with `lc > 0`; the `f` are pairwise coprime and `m` increases. `c` is `sign(lc) * content`. A constant `a` gives `(a[0], [])`; `[]` gives `(0, [])`. |
| polyb | `divisors(n, lim=0)` | 7 | `(sorted divisors <= lim, complete)`. `lim = 0` means all of them. Trial division runs to `TDMAX = 10^4`. An unproved cofactor counts as one prime, and then `complete` is False. More than `DIVCAP = 1024` divisors gives `([], False)`. |
| | `ratroots(a)` | 6 | `(roots, cof, complete)` for `a != []`. `roots` is a list of `(p, q, m)` with `q > 0` and `a = cof * prod (q*x - p)^m`. They come in candidate order (q ascending, then \|p\|, + before -), **not sorted by value**. `complete` means `cof` has no rational root. |
| | `gjsolve(rows, nv)` | 7 | Gauss-Jordan over Q on integer rows, fraction-free and gcd-reduced. Columns `< nv` are unknowns; the rest are right-hand sides (several are allowed). It returns `(piv, rows)`: pivot columns ascending, `row[piv[k]] > 0`, zeros in the other pivot columns, content 1. `None` means inconsistent. Solution: `x[piv[k]] = (row[nv] - sum of free terms) / row[piv[k]]`. |
| | `bezout(a, b, c)` | 6 | `(s, t, d)` with `s*a + t*b = d*c`, `deg s < deg b`, `d > 0` minimal. `None` unless `a`, `b` are nonzero and coprime. Any `deg c` is allowed. |
| polyc | `madd(a, b, k=1)` | 7 | `a + k*b`. `madd({}, a, c)` scales. |
| | `mmul(a, b)` | 7 | product. Dividing by a monomial `x^e` is `mmul(a, {(-e1, ..., -en): 1})` when the result has no negative exponents. |
| | `mpow(a, n, nv)` | 6 | `a^n`, `n >= 0` |
| | `mcont(a)` | 7 | integer content |
| | `mdeg(a, nv)` / `mmono(a, nv)` | 7 | the degree per variable / the monomial content (the least exponent per variable), as lists |
| | `mdivex(a, b)` | 6 | the exact quotient, or `None`. Lex division whose steps are bounded by the box `deg a - deg b`, so non-divisible input stops early. `b != {}`. |
| | `mkron(a, D)` / `munkron(p, D)` | 7 | Kronecker substitution `x_i -> x^(D0*...*D(i-1))` to a dense list, and back by mixed-radix digits (the last variable takes the rest). It is one-to-one while every exponent of `x_i` is `< D_i`. |
| | `mrel(a, k, q, c)` | 7 | reduce with `x_k^q = c`: `i` as a variable (`q = 2, c = -1`), or an integer radical |
| | `mcoef(a, k)` | 7 | the coefficients in `x_k`: a list by degree of dicts, with `x_k`'s exponent set to 0 |

## Deviations from DESIGN.md, and why

1. **No cross-part calls and no `import run`.** §4.3 allows `R.MODS['polyb'].f(...)`, but every
   part here is self-contained. So the family can be tested before `run.py` (T1.6) exists, and no
   part can fail because a sibling was evicted.
2. **The Kronecker multivariate gcd is not in CVPOLY.** §4.3 puts "Kronecker gcd" in `norm`, so
   T1.10 composes it. polyc provides the pieces. The tested reference recipe is `kron_gcd` in
   `tests/test_poly.py`; see "For T1.10" below.
3. **The sparse coefficients are ints, not NUM tuples** (§8.6 says "coefficient tuple"). A NUM
   tuple needs `K.nadd`/`K.nmul`, which would be a node dependency, and T1.2 must have none. norm
   clears the denominators (one integer denominator per polynomial). For Gaussian coefficients it
   can make `i` a variable and reduce with `mrel(p, k, 2, -1)`, or fall back to the content-only
   gcd of §8.6.
4. **No `prem`.** `pdivrem` returns the reduced pseudo-division, and the PRS uses it, because a
   scalar multiple of the remainder gives the same primitive part. `pevalq` was dropped for the
   line budget. `ratroots` tests each candidate by exact synthetic division by `(q*x - p)`, which
   is equivalent to testing it with `q^n * P(p/q)` (Gauss's lemma).
5. **Bezout is a square Sylvester-type linear system solved by `gjsolve`, not extended Euclid.**
   This reuses the solver and saves about 25 lines. It handles any `deg c` (the general
   diophantine `s*a + t*b = c` that Hermite reduction and partial fractions need), and it costs
   O(N^3) with `N = max(deg a + deg b, deg c + 1)`. That is fine for the partfrac cap of
   denominator degree <= 12.
6. **The levels are deeper than the §17.1 list for the leaves.** The drivers `yun` and `pgcd`
   are at L4 and L5, as §17.1 puts them. `pprim` and `pdivrem` are at L6 because they call
   `pcont`. Everything else is a leaf at L7. All of it can be called from L3 algorithms; from L4
   helpers, everything except `yun`.
7. **The `ratroots` order is the candidate order.** Sorting did not fit in the 150-line part.
   solve sorts the roots numerically anyway (§11.2), and the printer orders factors (§12.3).
8. **Root bound.** `ratroots` prunes candidates with a Fujiwara-type bound (`|root| <= 2*bnd`,
   with `bnd^k * |lc| >= |a_(n-k)|`), and also by `(q-p) | f(1)` and `(q+p) | f(-1)`.
   `divisors(a0, bnd*|lc|)` builds only the divisors under that bound, which keeps the lists
   short and the entries small ints. The candidate budget is `RRMAX = 4000` tests.

## Known gaps and TODOs

- **No cancel polling or `MEMFREE` checks inside the family,** because it has no node import. Every
  loop is bounded:
  - by `TDMAX`, `DIVCAP` and `RRMAX`;
  - by the caller's sizes: Gauss-Jordan is O(N^3) and the PRS O(deg^2) steps. Callers keep
    degrees under their caps (`KRONMAX`, `MAXTERMS`, partfrac 12) and poll between calls.
- **`ratroots` stays incomplete when** a constant or leading coefficient has a cofactor that trial
  division to 10^4 cannot prove prime, when the divisor list under the bound exceeds `DIVCAP`, or
  when the budget runs out. It never returns a wrong root, and it reports `complete = False`.
  - For T1.11/T1.12: in that case, refine with numeric real roots (factorb). For each approximate
    root `r` and each `q | lc`, test `pdivex(f, [-round(r*q), q])`.
  - p/q is in lowest terms whenever `a` is primitive or `complete` is True. A non-primitive `a`
    with incomplete divisor lists could, in theory, give a non-reduced `(p, q)`; the identity
    still holds.
- **No GCDHEU or modular gcd.** The primitive PRS is fine at calculator sizes.
- **polyb is at 149/150 lines and 2.96/3 KB, with no headroom.** If it has to grow, move the seam:
  `gjsolve` and `bezout` (69 lines) can become their own one-part family, or M0.5 can raise
  `LAZYMAX`. Lint's family rule only knows the part suffixes `b` and `c`, so a fourth `polyd` part
  would need a lint/manifest change.

## For downstream tasks

- **T1.10 (norm), the Kronecker gcd.** Use the `kron_gcd` recipe in `tests/test_poly.py`:
  1. strip each input's monomial content (`mmono`, then `mmul` by the negated exponent);
  2. take `D_i = max(deg_i a, deg_i b) + 1`, and enforce `KRONMAX`;
  3. `pgcd(mkron(a, D), mkron(b, D))`, then `munkron`;
  4. verify with `mdivex` on both;
  5. multiply back the componentwise-min monomial.

  Step 1 matters. Without it about half of random inputs fail: `x^2` in `a` and `y` in `b` both
  map to powers of X and leave a spurious common factor. With it, about 93% of random 2-3 variable
  cases get the full gcd. The rest are other spurious image factors, and retrying with a larger D
  rarely helps. Then the §8.6 fallback applies (content plus monomial gcd).

  The resulting gcd has `lc > 0` in the Kronecker order (the last variable leads), so normalize
  the sign as norm needs. A univariate `normal` should call `pgcd` directly on dense lists.
- **T1.11 (factor):** `pcont`, `pprim`, `yun`, `ratroots` (sort the factors yourself), `pdivex`
  for Kronecker candidates, and `ppow`/`pmul` for the product check. `yun` already returns
  primitive factors with `lc > 0`.
- **T1.12 (solve):** `yun`, then `ratroots` on each square-free part; `gjsolve` for linear systems
  (clear the denominators of each equation row first; several RHS columns are allowed). Free
  variables are the non-pivot columns `< nv`.
- **T2.5 (partfrac, Hermite):** `pdivrem` for the polynomial part. `bezout(a, b, c)` solves
  `s*a + t*b = c` for coprime `a`, `b` directly. In Hermite reduction use `bezout(V, V', C)`.
- **T3 (Faulhaber, ODE constants):** use `gjsolve` with integer rows.
