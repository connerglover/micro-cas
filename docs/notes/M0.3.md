## What was built

All probes share these properties.

- **Pager.** `out(s)` prints lines of at most 30 characters. A long line wraps at a space, and
  the continuation starts with one space. After 8 lines the probe prints
  `-- pN: screenshot, key --` and waits for a key. `page()` ends a page early. Every probe starts
  with `NAME v1` and ends with `== NAME end, pN ==`, where N is the number of pages, so the
  screenshots can be checked for completeness.
- **No waits on the desktop.** Without `ti_system`, `_wk` is a no-op, so a desktop run never
  waits. PROBE7 and PROBEK2 stop early with `no ti_graphics: stop` or `no ti_system: stop`.
  PROBE6 prints `poll no ti_system`.
- **Language subset.** The probes use only Python 3.4 syntax and ASCII. Glyphs are made with
  `chr()`. The probes may use lambdas and comprehensions on purpose, because PROBE5 measures what
  they cost.
- **Depth.** Code that runs at depth 9-10 (`t_exc`, `t_gc`, `t_cmp`, `t_sort`) calls only natives
  (`t_cmp` calls `memfree` at 10). `out()` calls only natives, so it is safe up to depth 9.
- **Clock.** `clock()` picks `time.monotonic`, then `perf_counter`, then `ticks_ms` (scaled), then
  `time.time`.

| line | how to read it |
|---|---|
| `impl ...` | `sys.implementation`: the MicroPython or CircuitPython version and `_mpy`. Needed to build `.mpy` files. |
| `maxsize` | 2147483647 means a 32-bit build, so small ints are below 2^30 |
| `nobi:` ... `nogc:` | names that are **missing** (`-` = none). Update device-python §4. |
| `nosyn:` | snippets that fail on the device. Expected to fail: `fstr walrus [*a] {**d} f(*a,*b) 1_0 annot varannot async`. CPython fails only `slots`. |
| `pow3` ... `slice` | values or `E:<exception>`. The desktop values are in the dry-run output, and device-python §14.1 lists the expected CPython ones. |
| `dictord`, `stable ... kcN` | CPython gives `xambzcqe` and `bdfhjlacegik kc12`. A different value confirms the [A] rows on hash-order dicts, unstable sort, and a key called per comparison. |
| `name c/i Err` (plain, sortk, map, minkey, eval, lcomp, genexp, eq, init, hash, str, add) | `c` is the count reached, `i` is the count if the construct costs no hidden frame. Hidden frames per level ≈ `i/c − 1` (e.g. `lcomp 5/9` means a comprehension costs 1 frame; `sortk 4/8` means the native key trampoline costs 1). |
| `lamb c/10` | 10 means a lambda costs exactly 1 frame |
| `imptop c/9`, `impfn c/7` | the ideal means a module body costs exactly one frame; one less means the import machinery costs one more frame (then lazy loads must start at depth ≤ 1 lower than §17.2 plans) |
| `nest D op` + ` E:X` | native recursion over nested tuples. `E:RuntimeError` means native recursion is depth-checked (safe, but limited). A freeze after a line means it is unchecked. Set `MAXNEST` below the last depth where everything passed. |

### PROBE6 (DESIGN Appendix B)

This is the Appendix B listing, with these changes (deviations):

- **`genB8`**: bytes per suspended generator with 8 locals (a typical `g_*`).
- **`cmp src`, `cmp6`, `cmp8`, `cmp9`**: `exec` of a generated 300-line, prototype-shaped source
  at depths 6, 8 and 9, reporting `ok <bytes held by the defined functions>`. This is a proxy for
  `imp6` that works before M0.5 exists, and B/300 is an early steady-bytes-per-line figure. `imp6`
  (import of `PRBL300`) is kept and reads `E:ImportError` until M0.5.
- **More `math` cases**: `exp1k logm1 infinf intinf nanck`. `nanck` evaluates `v - v != 0` for
  nan, inf and 1.5, and must print `[True, True, False]`. Anything else breaks the nan/inf check
  in `nrun` (§6.6).
- **`CHAIN = None`** now runs before `imp6`/`cmp*` (in the listing it was still alive). That frees
  about 32 KB for the compiles. `gc10` still runs with the chain alive.
- **The poll is split** (review #13 intent, confound removed). There are 3 s that poll only
  `escape()`, then a drain that counts queued keys, then 3 s that poll only `get_key()`. The user
  taps CLEAR during both phases. In the combined loop of the listing, `get_key()` could consume the
  press before `escape()` saw it. Afterwards a time-based `drain` waits for 0.5 s with no key, so a
  held CLEAR cannot auto-repeat into the next page's wait.
- **`free`** is printed before the poll.

| line | how to read it |
|---|---|
| `plain` | 10 (it starts from module level) |
| `ingen` | **6**: `send` costs no frame and the trampoline holds (the T1.6 gate passes). 5: `send` costs 1; take one level off L2-L7 or use the fallback (§10.8). The desktop gives `plain − 4`, and the test asserts this. |
| `tramp` | `200 201` |
| `throw` | `1 2` |
| `ret` | `val=7` or `noattr` |
| `genB`, `genB8` | bytes per suspended generator (none on the desktop: 0) |
| `del`, `bytea`, `time` | as Appendix B |
| `math <case> <value or exception>` | as Appendix B; `nanck` as above |
| `exc9`, `exc10`, `gc10` | as Appendix B (§17.2 fallbacks) |
| `cmp6/8/9 ok B` | compiling 300 lines works at that depth. `E:RuntimeError` at 6 means the compiler spends the depth budget: move `need` into the driver (§17.2). At 8 or 9 only, it is margin information. |
| `imp6` | as Appendix B (needs `PRBL300`) |
| `poll esc H q Q n N` | H `escape()` hits in 3 s while CLEAR was tapped; Q keys still queued afterwards (Q > 0: `escape()` does not consume the press, which the M0.2 shim's one-consumer model must then follow); N loops in 3 s (loop speed) |
| `poll keys K... n N` | codes `get_key()` returned. `esc 0` with 45 here means the `get_key` adapter is needed (§16.10). |
| `free` | free heap |
| `sort9` | `ok ok ok`; a freeze after `sort mode 1` or `2` means `K.isort` is needed (§17.2) |

### PROBE7 (Appendix B, written here)

The probe runs in this order:

1. identity and the `.mpy` import;
2. the paged `dir()` of `ti_graphics` and `ti_draw`;
3. an instruction page;
4. drawing measurements: the results are collected in `RES`, because the screen shows drawings;
5. the glyph sheet (a screenshot);
6. the interactive loop;
7. `disp_clr()`, then the results, paged.

The user answers each question with ENTER (yes) or CLEAR (no). The probe also checks the pixel
buffer itself with `getPixel`, so the answer does not rest on the user's eye alone.

| line | how to read it |
|---|---|
| `impl`, `mpy ver` | `sys.implementation` and its `_mpy` (`-` if absent) |
| `mpy import ok mpy 41` | `.mpy` works: switch the bundler to `.mpy` (§18.7). `E:ImportError` means the file was not sent or `.mpy` is not searched. `E:ValueError` (incompatible .mpy) means `.mpy` is supported but the version is wrong: rebuild `PRBMPY.mpy` with the matching `mpy-cross` (see below). |
| `ti_graphics N names:` | the full name list (the head scrolled off in PROBE) |
| `setColor rgb/tup/int ok/same/E:x` | which `setColor` forms work, checked by reading back a filled rectangle |
| `gp red (r, g, b)` | `getPixel` format after drawing pure red. 248 means RGB565. |
| `setPixel xyc/xy` | `setPixel(x, y, color)` or `setColor` + `setPixel(x, y)` |
| `scr WxH` | the pixels that store colors, scanned from (0, 50) and (50, 0). This is the §16.1 drawable size. |
| `neg x a y b corner c` | 1 if negative coordinates store pixels (an offset origin); `corner` checks (W−1, H−1) |
| `fdef M(w, h)` | `string_size("M")` before any `setFont` |
| `setFont ok ...`, `setFont bad n:Err` | the font numbers 0-5 that are accepted |
| `fN M(w, h) 10M(w, h)` | `string_size` per font (for the §13.3 metrics) |
| `default font N` | the font whose `M` size equals `fdef` (−1: unknown) |
| `fN Mbox xA..B yC..D` | ink bounding box of `M` relative to `drawString`'s (x, y). C ≥ 0: y is the top. C < 0: y is near the baseline (ascent ≈ −C). |
| `fN own/wide/tofu/q/none/E: labels` | glyph classes. The labels are `A pi rt int Sig inf apx le ge ne to th dot sq2 q cjk`: π √ ∫ Σ ∞ ≈ ≤ ≥ ≠ → θ · ², with `A`, `?` and U+4E00 as references. `own`: a distinct drawing, probably real (confirm on the glyph-sheet screenshot). `wide`: over 1.5× the width of `M`, probably UTF-8 bytes drawn as separate glyphs. `tofu`: same as U+4E00. `q`: same as `?`. `none`: no ink. `E`: raised. |
| glyph sheet (screenshot) | one row per font (up to 4): `fN`, then π √ ∫ Σ ∞ ≈ ≤ ≥ ≠ → θ · ² |
| `text dy D lh L` | the offsets the probe used for its own text |
| `fill`, `str`, `setpx`, `getpx`, `frame` | the cost per call: a full-screen `fillRect`, a 9-character `drawString`, a pixel, and a full redraw (background, border, title, box) |
| `redraw full`, `redraw box` | ms for the first frame, and ms per step-box region redraw |
| `steps y y y y y` | the drawing was visible at each `wait_key` (n = not seen) |
| `px steps kept ...` | the pixel buffer kept the border after each key |
| `after print: a px p` | whether the drawing survived `print()` (user, buffer) |
| `after disp_clr ok: a px p` | whether `ti_system.disp_clr()` erased it. **`y` means the box was still there (not erased)**. |

### PROBEK2 (§16.4)

The probe is guided. It names the 49 TI-84 Plus CE keys in keyboard order (`KEYS`). `2nd` is
placed before `sin` and `alpha` before `math`, so modifier separation shows up in the codes
again, and no OS combination (2nd+mode = quit, 2nd+on = off) can be hit by accident. A code that
differs from the [D] code is asked for again: a second press that agrees confirms a new code
(`new`), a press of the expected key corrects a slip, and three presses that never agree are
flagged `?`. Then:

- `get_key`/`getKey` with no key pressed (1 s each);
- RIGHT held for 3 s, with a drain afterwards;
- free capture of keys not in the list, until CLEAR is pressed 3 times;
- the results;
- the ON key last (it may raise KeyboardInterrupt and end the program, which is also an answer).

| line | how to read it |
|---|---|
| `match K of 49` | keys whose code equals the [D] code of §16.4 |
| `<name> <code> exp <d> new/?` | one line per key that differs |
| `codes ...` | all 49 codes in `KEYS` order |
| `idle get_key v... nN` | values with no key pressed (expected 0), and calls in 1 s: the cost of the `get_key` adapter |
| `hold right: 26 xC` | C > 1 means auto-repeat while a key is held (left/right scrolling) |
| `extra c...` | codes of keys the list did not name. The user's README reply gives their names. |
| `on code N`, or `on E:KeyboardInterrupt`, or the shell's own interrupt message | how [on] arrives (device-python §14.2) |

### PRBMEM (device-python §14.3 + §18.7)

`MODS = ("PRBMOD", "PRBL100", "PRBL200", "PRBL300")`. Missing modules print `NAME missing`.

| line | how to read it |
|---|---|
| `start` | free heap at the start |
| `tup2 ... tup9`, `list3`, `dict2`, `inst2`, `float`, `int64`, `str20`, `clos`, `gen` | bytes per object (N = 200). `tup4` is a NUM node, `tup5`/`tup7`/`tup9` are ADD/MUL nodes with 2/3/4 pairs. These give `NMAX` (§18.7). |
| `slot` | bytes per list slot holding a small int (the `N/H/NX/V` tables, §5.1; expected 4) |
| `arr` | bytes per `array('i')` element |
| `dent` | bytes per dict entry (a dict grown to 400 keys) |
| `sys.modules yes/NO` | |
| `delmod ok/stays reimport new/same` | `del sys.modules[n]` works, and a re-import builds a new module |
| `dictclr ok/no effect` | `m.__dict__.clear()` works |
| `NAME cost C ms T` / ` kept K1 k2 K2 kD KD` / ` peak P` | C is the steady RAM after import. T is the import (compile) time. K1 is RAM not freed by the first eviction (it includes the qstrs, which are permanent). K2 is the same for a second import/evict cycle (≈ 0 if eviction works). KD is a third cycle with `__dict__.clear()` first. P is the compile peak (ballast search). M0.5 derives `FACTOR`, `PEAKB`, `LAZYMAX` and the eviction mechanism from these. `PRBMOD` comes first and was already imported by the `delmod` check, so its K1 has no qstrs. |
| `end` | free heap at the end |

### PRBMPY.mpy

Built with `mpy-cross 1.29.0.post2` (MicroPython v1.29.0, **mpy v6.3**, bytecode only), installed
into a temp directory, not into `.venv`. The source (deliberately not in `probe/`: a `PRBMPY.py` on
the calculator would shadow the `.mpy`) is:

```python
# PRBMPY: compiled to PRBMPY.mpy by mpy-cross; PROBE7 imports it
K = "mpy"


def f(x):
    return 2 * x + 1
```

`PROBE7` prints `mpy import ok mpy 41` when it loads. If `impl`/`mpy ver` show an older MicroPython
or CircuitPython, rebuild it with that version's `mpy-cross` (`pip install mpy-cross==1.18` gives
mpy v5). CircuitPython needs its own `mpy-cross`.

## Tests (`tests/test_probes.py`, 18 tests, about 14 s)

- **Static checks** for every probe:
  - the device name matches `[A-Z][A-Z0-9]{0,7}`;
  - ASCII only;
  - none of: f-strings, walrus, annotations, async, match, positional-only or keyword-only
    parameters, PEP 448, `raise from`, the `__main__` guard, `1_000`;
  - imports only from the device module set or `PRB*`;
  - `compile()` succeeds.

  `PRBMPY.mpy` must start with `M` and a version byte of 5 or more.
- **Fallback dry run** of each probe (no `ti_*`), in a fresh interpreter running
  `from NAME import *` in a copy of `probe/`. It must exit with 0, print no line over 30
  characters, have no page over 9 lines, and start and end with the framing lines.
- **Stubbed dry runs.** Stub `ti_system` and `ti_graphics` modules are written into the temp
  directory:
  - `wait_key` replays `STUB_KEYS` and prints the marker `@K`;
  - `get_key` returns `STUB_GETKEY` for `STUB_HOLD` seconds after a wait;
  - `escape` returns True on every 9th call;
  - the graphics stub is a 320×210 RGB565 frame buffer, with a pattern font that lacks ∫ and has
    a top-left or baseline anchor.

  The tests assert the page lengths and the key results:
  - PROBE6: `ingen == plain − 4`, `tramp 200 201`, `exc9/exc10/gc10 ok`, `imp6` with a stand-in
    `PRBL300`, `cmp6/8/9`, both poll phases, `sort9 ok ok ok`, `nanck`;
  - PROBE7: `scr 320x210`, the setColor/setPixel forms, the fonts, ∫ as tofu, the anchor offset
    for both anchors, the loop answers;
  - PROBEK2: a slip, a confirmed new code, a `?` key, an extra key, idle, hold, ON;
  - PRBMEM, with a fake `gc.mem_free` so that the ballast search runs: `PRBMOD` and a stand-in
    `PRBL100`, the eviction checks, all shapes.
