# T1.3: Token passes (notes)

Files: `src/parse.py` (the T1.3 part: tables, `classify` and its hook, `lex`, `ti_rewrite`,
`ti_implicit`, `rpn`, `untok`, and their L7 helpers), `tests/golden/tiinput.txt`,
`tests/test_tokens.py`, `tests/test_rpn.py`. T1.5 adds `inst`, `tcode`, `expand_names`,
`g_eval` and `tokens` to the same module.

## Public API (as implemented, DESIGN.md section 7)

- **Tokens** are `(kind, value, start, end, flags)`.
  - Kinds: `K_NUM K_NAME K_OP K_LP K_RP K_LB K_RB K_COMMA K_POST` (0..8).
  - `K_NUM` holds `(p, 1)` for an integer, or a float for any number with `.` or `E` (D8, D14).
  - `K_OP` values are `+ - * / ^ = != < <= > >= => :=`. `:=` is an extra: stage 4 writes it
    for `f(x)=...` and FlowCE accepts it typed.
  - `K_LB`/`K_RB` hold `[ {` / `] }`. `K_POST` holds `!` or `'`.
  - Flags: `F_IMPL = 1` marks a `*` inserted by stage 4 or 5, which has `start == end`.
    `F_CALL = 2` marks a name whose `(` opens a call. Every pass keeps this rule: a name has
    `F_CALL` only when the next token is `(`.
  - Tokens made by a pass (an implicit `*`, the `(` `)` of `sin x`) have `start == end`, or
    span the blanks they replace.
- **`classify(name)`** `#@L 7` returns `C_UNK C_VAL C_FN C_KEY C_UFN` (0..4). It reads the
  module tables `FNAMES`, `VNAMES` and `KWORDS`, plus the hook **`SESS`**.
  - `SESS` is any object with the dicts `VARS` (VALUE), `FUNCS` (USERFN) and `CMDS`, `ALIAS`,
    `MACROS` (FUNCTION). It is `None` until set; with `None` there are no session names.
  - The alias `d` is never FUNCTION by class (D9). `iscall` decides it.
- **`iscall(v, c, ode, w, q)`** `#@L 7` decides whether the name `v` (class `c`) opens a call
  with the `(` at `w[q]`. That holds for FUNCTION/USERFN; for the call letters `f g h`; for
  `y y' y'' u` when the line contains `desolve`/`dsolve`; for any uncut UNKNOWN name of 2+
  letters (FlowCE); and for `d` with a top-level comma (D9).
- **`lex(s)`** `#@L 6`: text -> tokens. It sets `F_CALL` through `iscall`, so the short paths
  (`tcode`, answer text, the 2D layout) parse `sin(x)` and `foo(x)` as calls.
  - Errors: `CasError('invalid character', pos)` and `CasError('number too large', pos)`.
- **`ti_rewrite(toks)`** `#@L 6`: stage 4, paper notation. **`ti_implicit(toks, cut=1)`**
  `#@L 6`: stage 5. `cut=0` is FlowCE's `split_unknown = false`. Neither changes its input
  list. Both are idempotent, and stages 4+5 run twice give the same tokens as run once.
- **`rpn(toks)`** `#@L 7`: the shunting-yard of section 7.7, with the item shapes of the
  section 7.7 table. `('w', ...)` items are never made here (see T1.5 below).
  - Errors are `CasError(msg, pos)`, where `pos` is a source offset. The messages are
    `missing operator`, `missing operand`, `missing (`, `missing )`, `empty argument`,
    `empty ()`, `unbalanced`, `mismatched bracket` and `too deeply nested` (`MAXNEST = 32`).
- **`untok(toks, s=None)`** `#@L 7`: tokens -> text.
  - With the source `s`, typed blanks and number text are kept, so `untok(lex(s), s) == s`
    unless `s` contains the pi or theta glyph.
  - Without `s`, it puts a blank between tokens only where they would otherwise lex as one
    (`x y`, `2 3`, `2 E5`, `2E- 3`). So `lex(untok(t))` gives back `t`'s kinds and values.
    This is the form for a definition's body text, if T1.6 wants it.

## Deviations from DESIGN.md and FlowCE

All of these are recorded in `tests/golden/tiinput.txt` with a `# deviation` line.

- **The FlowCE port.** Every FlowCE output holds verbatim except where cas-evo rules differ.
  The differing rules are: no strings, comments, `_` units or `0x`/`0b` literals (they give
  `invalid character`, or `0*x1F`); one line, with no control characters; D14 for `e`; and the
  pi and theta glyphs, which lex as the names `pi` and `theta`.
- **`sin^-1.5(x)` stays as typed.** `^-1` must be the whole number 1. FlowCE gives
  `asin(.5)(x)`.
- **Stage 4 re-scans what it builds.** The argument and exponent of a rewrite go back on the
  work list (section 7.4's splice), so `sinx^sinx` becomes `sin(x^sin(x))` in one pass. FlowCE
  copies them verbatim and needs a second pass.
- **Two new rules for idempotence.** The random-line property found FlowCE inputs where a
  second pass changes the result. Both cases are garbage input.
  1. A FUNCTION/USERFN/KEYWORD name is never an exponent (`scan`, run=0). Before the fix,
     `sin^sin^n(x)` became `sin^sin(x)^n` and then `sin(x)^sin^n`. Now `sin^sin(x)` stays as
     typed, and `sin x^sin x` becomes `sin(x)^sin(x)`.
  2. Stage 5 does not cut an UNKNOWN name that starts with a function name of the `FNT`
     table: `lncos(x)`, `lnpi(x)`, `expi(x)`. Stage 4 had left `ln lncos(x)` whole because the
     name starts with `ln`. FlowCE cuts it into `l*n*cos(x)`, and a second stage 4 then reads
     `ln l` as `ln(l)`.
- **`y'` is one name** (section 7.2). So `y'(0)` without `desolve` on the line is `y'*(0)`,
  where FlowCE gives `y'(0)`.
- **`f(x)= ` with only a trailing blank** is not a definition (the token view), where FlowCE's
  character view makes it one. `f(x)=>y` is not a definition either, because `=>` is one token.
- **`classify` hook.** Section 7.3 says the tables are CVRUN globals read with no call. parse
  cannot import run (run imports parse), so `classify` reads them through `P.SESS`.

## For downstream tasks

- **T1.6 (run):**
  - Set `P.SESS = R` (the run module) before any input is parsed. The simplest place is
    `casevo.py` right after the imports. Run's own tests need a fixture that does the same.
  - `R.go` must split a top-level `=>` (and `:=`) before `rpn` (sections 7.7 and 7.9).
    `rpn` gives `=>` the lowest precedence, but a bare top-level list is closed only at the
    end, so `1,2=>a` would come out as `[1, 2=>a]`.
  - Definitions: stage 4 turns `f(x)=body` into `f(x):=body` at the start of a line. The
    first token keeps `F_CALL` and is never rewritten. `untok(body_tokens)` (no source) gives
    a body text with explicit `*` that needs only `lex`.
  - `CasError` from these passes has two args: `(message, source offset)`.
- **T1.5 (builders):**
  - `tcode` is `rpn(lex(s))`. Wildcards are `('s', 'A', ti)` items, so `inst` decides by
    the letter. `rpn` never makes `('w', ...)` items.
  - `log10` is FUNCTION (it comes from FlowCE's paper-notation table), so `g_eval` should map
    `log10(u)` like `log(u)`.
  - Unknown calls such as `foo(x)` come as `('F', 'foo', n, ti)`.
  - `K_POST "'"` reaches `rpn` only on a non-`y` name, as `('o', "'", ti)`; reject it.
  - `rpn` also passes `('o', ':=', ti)` through, if a `:=` is ever nested.
- **Optional functions** (section 15.2: `re im conj arg round ...`). Add them to `FNAMES`
  when their builders exist. Until then `re(z)` is cut into `r*e*(z)`.
- **T1.7 (`messages.txt`):** the `rpn` and `lex` messages are listed above.
- **Size.** The T1.3 part of `parse.py` minifies to about 660 device lines. The manifest
  budgets 440 for the whole module, and T1.5 adds the builders on top. The large functions
  are `ti_rewrite` 170, `ti_implicit` 112, `rpn` 95, `lex` 70, `scan` 54 and `untok` 46.
  `untok` is used only by tests unless T1.6 adopts it. The size gate (B.1) and the section
  18.8 ladder will need to look at this. One option is a lazy part holding stages 4-5, loaded
  only for typed input.
- **Exceptions are created at depth 6-7** with a dynamic position. If PROBE6's `exc10` fails,
  the preallocated-instance fallback of section 17.2 cannot carry the position.

## Tests

- `tests/test_tokens.py`: 137 non-slow tests and 1 slow test.
  - The golden file has 266 FlowCE cases in FlowCE order (67 rewrite, 189 split, 10 no-split),
    plus 162 cas-evo cases (428 in all).
  - Named review cases (section 7.10/20.12 lexer row).
  - `lex`, `classify` and flag cases, and `untok`.
  - The random-line properties on 2,000 lines, and FlowCE's count of 20,000 in the slow test:
    only `*` inserted, stage 5 idempotent with and without cut, stage 4 idempotent, stages
    4-5 twice equal once, `F_CALL` only before `(`, the output re-lexes to the same tokens,
    and `classify` is called only on names.
- `tests/test_rpn.py`: 121 tests.
  - The section 7.7 table, precedence, lists, calls, groups, item indices and errors.
  - Random token lines give well-formed RPN or a `CasError`.
  - The RPN of `gen.py` expression text evaluates to the tree's value.
- Local fuzzing beyond the suite found nothing: 220,000 random lines with FlowCE's fake
  classifier and 100,000 with the real tables plus a session.
- lint and FRAMELINT are clean. All tests pass in the default and `--strict-depth` modes.
- **`parse` imports `node`** (for `CasError`), so conftest runs the node-table invariant scan
  after these tests. While T1.1 was editing the uncommitted `src/node.py`, that scan failed
  for a while (`H=0` on the preallocated ids), and so did every test that imports `parse`.
  The final runs, with the scan on, pass: 259 in the default mode and 258 non-slow in
  `--strict-depth`. If these tests fail only in the post-test scan, look at `node.py` first.
