## Public API as implemented

Levels in brackets.

### `norm.py` (part a; `R.MODS['norm']`)

- **`normal(e, ex=0)` [3]**: one fold over `postorder(e)`.
  - Every node maps to a fraction `(num, den)` of polyc polynomials (dicts `{exponent tuple:
    int}`) over a fixed number of kernel slots. The tuple length is an upper bound from a
    pre-pass. Slot 0 is `i`, with the relation `i^2 = -1`.
  - **Kernels** are symbols, constants, floats, function nodes (with normalized or expanded
    arguments), `CALL`, `LST`, relations and the like (rebuilt through `A.rebuild` with
    converted children), `u^(1/q)` for a pair `u^(p/q)`, and any other power kept whole
    (`b^e` with a symbolic, complex or float `e`).
  - **Relations** `x_k^q = c` are kept for an integer constant `c`: `i`, and
    `sqrt(n)`/`n^(1/q)` with an integer radicand, including negative ones such as
    `(-2)^(1/4)`. They are applied in every product.
  - **`ex = 0` (normal, 8.6).** Negative powers go to the denominator. At the end `tonode`
    cancels:
    - the common monomial;
    - the gcd, through the Kronecker substitution of the T1.2 recipe (strip each side's
      monomial content, `D_i = max deg + 1`, `poly.pgcd`, `munkron`, check with `mdivex`).
      Above `KRONMAX = 64` (`prod D_i`) it cancels the content only;
    - the integer contents.

    It returns `k*N/D` with `N` and `D` primitive. The constructors normalize the signs, so
    equal rational functions give the same node (tested on random inputs). `normal` never
    raises a `CasError` or a `CasSoft`. On `oo`/`undef`, the caps, a hidden `1/0` or
    `Undefined` it **gives up**: it returns `e` and sets `GAVEUP[0] = 1` (`NORMAL_GAVE_UP`).
    So `rules.g_rewrite`'s NEAR test (`normal(d) == ZERO`) is exact for zero and never raises.
  - **`ex = 1` (expand, 8.5).** Integer powers >= 0 are multiplied out. A negative power, or
    any non-integer power that is not a positive rational, is an atom with its base (and
    exponent) expanded. Function arguments are expanded too: `sin(2(x+1)) -> sin(2x+2)`,
    `e^(2(x+1)) -> e^(2x+2)`. The denominator is a constant that divides every term, so
    `3(x+1)/2 -> 3x/2+3/2`. Expand raises:
    - `CasError('too large')`: more than `MAXTERMS = 400` terms, or more than
      `MAXCELLS = 3200` terms times slots, or more than `NVMAX = 64` slots;
    - `CasError('number too large')`: a coefficient over `MAXBITS` while powering;
    - `CasSoft`/`Undefined`, from the constructors;
    - `CasError('expression too complex')`: the node table is full. This is the real limit
      for big univariate results; see the gaps.
- **`tonode(n, d, ks, ex)` [4]**: a fraction to a node. It does the gcd and content work
  described above, then builds through `add_`/`mul_`.
- **`pmul(a, b, rl)` [6]**, **`ppow(a, n, rl)` [5]**, **`kmono(k, ks)` [7]**: the products
  with relations and caps, and the slot of a kernel.
  - `pmul` checks the running term count every 64 terms. So no dict ever holds more than
    `MAXTERMS + 64` terms. The same check polls `K.ESC` (Cancel) and `K.MEMFREE`
    (`CasMemory` below `LOWMEM`).
  - `ppow` checks the coefficient size after each squaring.
- **Commands** (registry family `norm`; `g_eval` reaches them through `R.need('norm')`):
  - `g_expand(args, ctx)`: `normal(e, 1)`;
  - `g_together(args, ctx)`: `normb.dfac(normal(e))`;
  - `g_simplify(args, ctx)` and `g_autosimp(e)`: forward to `normb.g_simp(e, 1)` and
    `g_simp(e, 0)`.
- Constants: `MAXTERMS KRONMAX NVMAX MAXCELLS M_LARGE GAVEUP`.

### `normb.py` (part b; `R.MODS['normb']`)

- **`g_iszero(e)` [2, generator]** returns `normb.YES = 2`, `A.NO = 0` or `A.LIKELY = 1`.
  - A number is decided exactly. A symbol, `pi`, `e`, `oo` or `undef` is NO.
  - Otherwise these steps:
    1. expand;
    2. `ID.lnsplit`;
    3. `rules.g_rewrite(., 'zbasis', 0, 64)`, only when sin..cot occur;
    4. `normal`.

    A `ZERO` there is YES. A nonzero rational function of symbols only is NO. Otherwise the
    answer is `A.nprobe(e)` on the **input**: NO is NO; LIKELY, or UNKNOWN (no usable real
    point), is LIKELY.
  - It releases everything it built (`K.keep(m0, None)`; the rule patterns stay). So it can be
    called with or without `scoped`; the result is a small int.
- **`g_simp(e, full)` [2]**: simplify (`full`), or the default result path. Inside lists and
  relations (solution lists) each expression is simplified on its own, then rebuilt.
- **`g_one(e, full)` [2]**: the candidates of 8.7. Only ADD, MUL and function nodes are
  touched. On the default path a result of `A.size >= AUTOMAX = 100` is left alone (FlowCE).
  The candidates, in order:
  0. `dfac(normal(e))`; or, for a product of polynomials with positive integer powers,
     `keep_factored` (its bases normalized), so `2(x+1)(x-1)` stays factored;
  1. `collect_rational`: the rational terms of a sum combined with `normal`, the rest kept
     (`1/(x-1)-1/(x+1)+sin(x) -> 2/(x^2-1)+sin(x)`);
  2. `trigsin` and 3. `trigcos`, each as rewritten and also then `normal`ized;
  4. `tlin`, then expand and `tlin` twice (so `sin^4-cos^4 -> -cos(2x)`);
  5. full only: `lncollect`; 6. `expmerge`; 7. `ID.denest`; 8. a rationalized denominator.
     The last one multiplies by the conjugate of the irrational terms of the denominator, so
     `1/(1+sqrt(2)) -> sqrt(2)-1`, `(x^2-2)/(x-sqrt(2)) -> x+sqrt(2)`,
     `(x-1)/(sqrt(x)-1) -> sqrt(x)+1` and `(e^(2x)-1)/(e^x-1) -> e^x+1`.

  The measure is `A.size(., True)`. The smallest candidate wins; a tie goes to the input. A
  candidate that would win is first checked with `A.nprobe(e, cand)`:
  - LIKELY: it is accepted;
  - NO: it is discarded and `SIMPBUG += 1`;
  - UNKNOWN: it is discarded with no bug counted.

  Each candidate runs in a region: after each one, `best = K.keep(m0, best)`.
- **`dfac(r)` [3]**: factors the denominator of a normal form `k*N/D` over Q (Yun, then
  `ratroots`), when `D` is a polynomial with integer coefficients in one kernel. It is used
  only when the result is not bigger: `1/(x+1)^2`, `(x+3)/(2(x+1)^2)`, `1/(x^2+1)^2`. Otherwise
  it returns `r` unchanged.
- **`kinds(e)` [6]**: bits. 1 means sin..cot occur; 2 means `e` is not a rational function of
  symbols; 4 means `e` has a negative power. **`dden(r)` [7]**: the sum `D` of `k*N/D`.
- Module state: `SIMPBUG` (the conftest checks it after every test), `YES`, `BUD = 64` fires
  per rewrite pass, `AUTOMAX = 100`.

## Deviations from DESIGN.md, and why

1. **`expand(e)` is `normal(e, 1)`, and `together(e)` is `normb.dfac(normal(e))`.** §8.1
   names three L3 functions. One fold serves both expand and normal. An L3 `expand` wrapper
   would be an illegal L3 -> L3 edge (FRAMELINT), and a second copy of the fold would cost
   about 80 lines. `together` is a composition, so call it from a generator.
2. **The command generators are in part a**, because `g_eval` gets the module from
   `R.need('norm')` / `CMDS[...][0] == 'norm'`. `g_simplify` and `g_autosimp` forward with
   one `yield` to part b. The forward costs no frame.
3. **Size: CVNORM is over `LAZYMAX`.** It has 210 minified lines in `norm` and 164 in `normb`
   (374 in all, against the §4.1 estimate of 300). `test_parts_fit_lazymax` is a strict
   `xfail` that records this; `test_parts_size_is_bounded` caps it at 210.
   - **Proposed fix** (not my files): a third part `normc`. This seam fits 150 lines per part:

     | part | contents | about |
     |---|---|---|
     | `norm` | `normal`, the forwarders, `g_iszero` | 118 lines |
     | `normb` | `kmono`, `pmul`, `ppow`, `tonode` | 115 lines |
     | `normc` | `kinds`, `dden`, `dfac`, `g_simp`, `g_one` | 142 lines |

     It needs these rows:
     - `run.py`: `DEV['normc'] = 'normc'`, `PARTS['norm'] = ('norm', 'normb', 'normc')`,
       `FAMILY['normc'] = 'norm'`;
     - `build/manifest.py`: `MODULES ('normc', 'CVNORMC', 'L', 150, 4)`, `PARTS`, `FAMILY`.

     After that, only `R.MODS[...]` keys in the forwarders change.
4. **Caps.** §8.6 asks for "at most 6 kernels and total degree 60". Instead:
   - `NVMAX = 64` slots, plus `MAXCELLS = 3200` (terms times slots), keep memory bounded
     when there are many kernels;
   - `KRONMAX` bounds the gcd (it implies at most 6 non-constant variables);
   - `MAXTERMS` and `MAXBITS` bound the arithmetic.

   With a 6-kernel cap, `expand` of a 7-symbol sum would fail, and nested inputs (§20.7, 32
   deep) would too.
5. **Gaussian coefficients.** `i` is a variable with a relation, not "content-only gcd".
   Cancelling a common factor of the polynomials in `(x, i)` is a valid identity. So
   `1/(x+i)-(x-i)/(x^2+1)` normalizes to 0. A gcd that needs the relation, such as
   `(x^2+1)/(x-i)`, is not found; the result is still correct.
6. **No relation for symbolic radicands.** `sqrt(x+1)` is a plain kernel. The final rebuild
   through the constructors still merges its powers, so `(sqrt(x)+1)^2-x-2sqrt(x)-1` is 0.
   But gcds that need `t^2 = u` are missed. `normal((x-1)/(sqrt(x)-1))` stays as it is;
   explicit `simplify` gets `sqrt(x)+1` by rationalizing.
7. **Kernels are numbered in discovery order**, not by `(H, tiefix)`. The result node is
   canonical anyway: the constructors sort, and the contents and signs are normalized. Only
   a Kronecker spurious-factor failure (rare, multivariate) can depend on the order.
8. **`normal` gives up on `oo`/`undef`** (the kernel arithmetic would cancel `oo/oo`).
   `expand` treats them as atoms and lets the constructors fold.
9. **`g_iszero`.**
   - UNKNOWN (no real point) is LIKELY, as §8.6's "otherwise LIKELY" and the T1.8 notes say.
   - Step 4 claims NO only for rational functions of symbols. `pi`, `e`, radicals and exp
     bases go to the probe, which decides constants well.
   - The ZBASIS step runs once. A `sin^2` created by `normal`'s own products is not
     rewritten again; at worst that gives LIKELY.
10. **Simplify candidates.** These differ from §8.7:
    - `merge_sqrt` has no candidate of its own: the constructors merge equal bases, and
      `normal` with the rebuild does the rest.
    - `power_sums` and abs factoring are not done (see the gaps).
    - Each improving candidate is verified as it is met, not only the final winner. So a
      winner that fails verification falls back to the best verified one, not to `A`.
11. **The univariate dense fast path of §8.5 is not implemented.** The sparse path is fast
    enough on the desktop: `together((x^60-1)/(x-1))` takes about 1 ms.

## Known gaps / TODOs

- **Big expansions hit `NMAX` before `MAXTERMS`.** Each result term costs about 3 nodes:
  - the `c*m` product from `mul_`;
  - the coefficient-1 monomial that `add_` splits off;
  - the coefficient.

  So `expand((x+1)^399)` gives `expression too complex`, while `(x+y+z)^20` (231 terms) and
  `(x+1)^150` fit. Building the ADD tuple directly from `(monomial, coefficient)` pairs would
  halve this. It needs the canonical sort and `tiefix`, plus a fallback for monomials that
  fold to numbers or sums.
- `power_sums`, abs factoring (explicit simplify) and `sin(2x)`-type multiple angles in the
  zero basis (T2) are not done.
- `together` factors only a denominator in one kernel with rational roots, plus the
  square-free parts. Irreducible quadratics stay, as in FlowCE.
- A cofactor of degree >= 2 with an irrational square-free part, such as `x^2-2`, stays
  expanded. Factoring over Q is complete only for the linear factors (no Kronecker
  quadratics here; that is CVFACT's job).
