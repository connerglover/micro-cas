## What the bundler does (DESIGN §19.2, phase 1)

1. It checks the manifest (`check_manifest`).
2. It lints `src/` with `tests/support/lint.py` and FRAMELINT. Any error stops the build, and
   nothing is written.
3. **Src name checks:**
   - every `src/*.py` has a manifest row (or is the entry);
   - lazy families are complete (all parts present);
   - no module imports the entry module;
   - no `from <src module> import`;
   - no dotted import of a src module;
   - no src module name in a string (`__import__('poly')`, `sys.modules['node']`).
4. **Per module:**
   - tokenize, then drop comments, the `#@` annotations, blank lines and **every string-only
     statement** (docstrings and bare strings);
   - **one device line per logical line:** continuation lines are joined;
   - a block left empty gets a `pass`, mapped to its header line;
   - a multi-line string literal is re-encoded on one line with `ascii()`;
   - 1-space indentation and minimal token spacing. Identifier-like neighbours get one space.
     Every line is re-tokenized to prove that it gives the same tokens; if not, it falls back to
     spaces between all tokens.
5. **Imports:** `import node as K` -> `import CVNODE as K`; `import node` -> `import CVNODE as
   node`. Natives are left alone.
6. **run.py tables.** These are written only for names that run.py defines as module-level
   literals (`NAME = literal`):
   - `DEV`: the literal's keys, with values mapped to device names;
   - `PARTS`, `FAMILY`, `CLOSURE`: restricted to the bundled families;
   - `CLOSURE` is derived from run.py's literal `DEPS`, leaf-first and ending with the family;
   - `LINES`, `COST`: per bundled lazy part. `COST` is `.mpy × FACTOR`, or
     `lines × MPYB × FACTOR` without mpy-cross;
   - `PEAKB`, `FRAG`: from the manifest.

   The desktop literals of `PARTS`, `FAMILY` and `CLOSURE` must agree with the manifest on every
   key they share, and `DEV` keys must be the manifest runtime keys. A mismatch is an error. A
   bundle with lazy modules but no `DEV` literal gives a warning.
7. **Write:**
   - `dist/device/<DEV>.py` (ASCII, LF). Stale `.py`/`.mpy` files are removed first.
   - `dist/linemap.json`: `{DEV: {"src": path, "lines": [[first,last], ...]}}`.
   - `dist/levels.json`: `{DEV: {func: level}}`, read by `pytest --bundled`.
   - `dist/sizes.txt`.
8. **Checks on the output:**
   - the line budget and `LAZYMAX` (L and U modules);
   - `compile()`;
   - the subset lint with `device_names=True`. A `#@float-ok`/`#@unordered-ok` error is
     silenced only if the marker is on the mapped source lines; errors are reported as
     `dist:line (src:line)`;
   - the size gate: `.mpy × FACTOR` ≤ KB budget, if mpy-cross is found. The lookup order is
     `MPY_CROSS=path`, then the `mpy_cross` package, then PATH. Otherwise there is a warning.

After a lint or manifest error nothing is written. After a later error the files are still
written (so they can be inspected) and the exit code is 1.

## Public API (build/bundle.py)

- `minify(text, name) -> Minified`, with `.lines`, `.spans` ((first, last) source line per device
  line) and `.text`. It raises `BundleError` on a syntax error or an f-string. **M0.5's genprobe
  should use this** for PRBL100/200/300; the line count is `len(m.lines)`.
- `rewrite_imports(m, {src: dev}, entry)` -> errors. It rewrites in place.
- `load_manifest(path)`, `Manifest(ns)` (lookups `rows() key_of src_of family_of parts_of`),
  `check_manifest(man)`.
- `families(man)`, `closure(deps, fams, family)`, `desktop_tables(man, deps)`.
- `bundle(src, dist, man=None, lint=True, sizer=default) -> Result`, with `.errors .warnings
  .files .lines .mpy .sizes`. `sizer`: path -> .mpy bytes; `None` skips the gate.
  `mpy_sizer()` finds mpy-cross.
- `linemap.load/lookup/describe/translate/main`.

## Manifest (build/manifest.py)

- `ENTRY`, `ENTRY_BUDGET`.
- `MODULES` rows `(src, device, class, max lines, KB budget)`, one per module and per part of
  §4.1/§4.3.
- `KEYS`: runtime key -> src where they differ. It must equal `framelint.KEYS`.
- `PARTS`: multi-part families, by runtime key.
- `FAMILY`: must match `PARTS`.
- `FACTOR PEAKB LAZYMAX FRAG MPYB`.

`check_manifest` keeps the manifest in step with the lint's module map:

- every `lint.ALIASES` module has a row, and every row has an alias;
- class R exactly when `lint.RESIDENT`;
- device names `[A-Z][A-Z0-9]{0,7}`, unique; modules also `CV[A-Z0-9]{1,6}` (§0.6).

**If you add a module to the lint map, add a manifest row (and the reverse).**

## Deviations from DESIGN.md (and why)

- **Budgets:**
  - Lazy rows use max lines = `LAZYMAX` (150), not the §4.1 estimates (ident 120, itab 100).
    The cap is the real limit.
  - KB per part is the §4.1 module KB divided by the number of parts, rounded up, at least 3.
    The `poly` rows match the §19.1 sketch (150, 3).
  - Resident rows follow the §19.1 sketch where it gives one (node 520/12, alg 300/7, parse
    440/10); the others use §4.1.
- **New manifest names:**
  - `KEYS`, `PARTS`, `ENTRY_BUDGET`;
  - `MPYB = 12.5` (.mpy B per line, [M]), for `COST` when mpy-cross is missing.
- **All string-only statements are dropped,** not only docstrings. They have no effect.
- **Continuation lines are joined,** so line budgets count logical lines. §4.1 "minified code
  lines".
- **The bundler writes all the §19.1 run.py tables,** not only `DEV`. It does so only if run.py
  defines them.
- **FRAMELINT on the bundled output is not run** (§17.3 last bullet). Phase 1 changes no names,
  and `minify` provably keeps the AST (tested on every repo .py), so it would re-check the src.
  For B.1 (phase 2 renames), framelint needs two changes from its M0.1 owner:
  - device module names (`CVRUN` for `run` in `IMPORT_OK`, `m.name == 'run'`);
  - an external level table, because the annotations are stripped.
- **Level table location.** It is `dist/levels.json` (by device name, as the M0.1 conftest
  expects), not `build/levels.json`.
- **No `build/sizes.py`** (§4 layout). The size report is part of `bundle.py`.

## For downstream tasks

- **T1.6 (run.py).**
  - Define `DEV`, `PARTS`, `FAMILY`, `CLOSURE`, `COST`, `LINES`, `PEAKB`, `FRAG` and `DEPS` as
    module-level literal assignments (`NAME = {...}`). Comments inside them are fine. Use one
    assignment per name, with no computation.
  - Desktop `DEV` maps runtime key -> **src** module name (`'int': 'integ'`).
  - `python build/bundle.py --tables` prints manifest-consistent desktop values. CLOSURE is
    derived from your `DEPS` once run.py exists.
  - The desktop `COST`/`LINES`/`PEAKB`/`FRAG` values are yours (fake sizes for tests); the
    bundler overwrites them.
  - Never write a module name as a string literal outside `DEV`.
- **M0.5 (memory gate).** You own the constants in the manifest:
  - `FACTOR`, `PEAKB`, `LAZYMAX`, `FRAG`, `MPYB` and the KB budgets;
  - `check_manifest` requires all of them to be present and positive;
  - the tests no longer pin their values.

  Generate PRBL* with `bundle.minify(...)`. Probe names are not CV-prefixed, so they do not go
  through `bundle()`.
- **T1.14/B.1.**
  - `pytest --bundled` against a real bundle is still untested end to end. The conftest side is
    M0.1's.
  - Phase 2 renaming, FRAMELINT on the output and `.mpy` output (if PROBE7 says `.mpy` imports
    work) are still to do.
  - `rewrite_imports` and the run.py table rewrite work on token lists (`Minified.items[i].toks`).
    A renaming pass can go in the same place.

## Known gaps

- The size gate is skipped (with a warning) unless mpy-cross is installed. It is not in
  `.venv`; `pip install mpy-cross` adds it.
- The `#@float-ok`/`#@unordered-ok` silencing is keyed on lint message fragments
  (`bundle.MARKERS`). If `lint.py` rewords those messages, update `MARKERS`.
- f-strings and t-strings are rejected (they are banned in src anyway).
