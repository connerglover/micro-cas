## What was built

### The probe modules (`python build/genprobe.py`)

- `generate(n)` writes exactly `n` device lines (checked through `bundle.minify`, so a line is a
  minified logical line, as in `LAZYMAX`). Code shapes come from the prototype and the DESIGN
  sketches: pair loops over flat tuples, `if` chains on op codes, the matcher's goal stack, dense
  integer-list arithmetic, a `g_int`/`g_sum` trampoline generator pair with `R.need`/`R.scoped`,
  the printer's string building, string and tuple tables. 19 templates.
- **Blocks.** A 2-line head, then 100-line blocks. Block k holds the templates of
  `GROUPS[k % 3]`, padded with one-line tables. The three groups were chosen (by search) to have
  the same line count (98/99/99 of 98/100/100) and parse density (11.1/10.6/11.3 AST nodes per
  line). So PRBL200 is PRBL100 plus block 2 and PRBL300 adds block 3 (with different names); the
  three sizes differ in size, not in kind, and the report fits a straight line (fixed part plus
  bytes per line) through them.
- **Names.** Every function and table carries the module tag (`a`, `b`, `c`) and a copy number,
  so each import interns its own names, like a real lazy module. Attribute names (`K.N`,
  `K.ONE`, ...) are shared, as real lazy modules share them with the resident ones.
- **Bodies only define** (functions and literal tables), so PROBE6 can import PRBL300 at depth 6.
  The modules pass the src subset lint (`lint.lint(..., device_names=True)`), and mpy-cross 1.29
  (MicroPython's own compiler) accepts them.

| PRBL100 | 100 | 11.0 | 1498 (15.0) | 6 (0) | 31 |

The probe code is slightly denser than ours, so the measured `PEAKB` errs high (safe).

### The gate (`python build/genprobe.py --derive FILE [--apply]`)

- `parse_prbmem(text)` reads a PRBMEM transcript typed from the screenshots: page prompts and
  framing are dropped; continuation lines (leading space or tab, or `kept`/`peak` typed on a new
  line) are joined; CRLF is fine. Unknown lines are returned in `unparsed`.
- `derive(res)` applies DESIGN §18.7:
  - `FACTOR = Σcost / Σ.mpy` (rounded up to 0.01), `BPL = FACTOR × MPYB` (steady B/line);
  - transient = `peak − cost + (kept1 − kept2)` (PRBMEM measures the peak after three cycles, so
    the names are already interned); `PEAKB` = the worst transient per line, rounded up;
  - `LAZYMAX` = the largest multiple of 10 with `LAZYMAX × PEAKB ≤ 12 KB` (the ledger's compile
    reserve). Below 150 it warns and also prints the reserve that would keep 150; at 300 or more
    it says families may be merged; below 50 it points at `.mpy` output and the ladder;
  - `NMAX` = 36 KB of node memory / (max(`tup4`, `tup5`) + 4 × `slot`), a multiple of 64;
  - `EVICT`: `'modules'` if `sys.modules` deletion works, re-imports a new module and leaks at
    most 2 KB per `LAZYMAX`-line part (k2 scaled); else `'dict'` if `__dict__.clear()` does
    that; else `'none'` (with the §18.5 consequences as a warning);
  - the ledger (§18.1) and the load sets (§18.2) with the measured numbers;
    `DRAW_EVICTABLE` = some load set does not fit with CVDRAW resident (ladder step 4); rows
    still short with CVDRAW evictable are listed (steps 5-7).
- `report(g)` prints all of it, the straight-line fits, the import times and the KB column of
  §4.1, and the manifest block. `--apply` (`apply_manifest`) rewrites only the `CONSTS` lines of
  `build/manifest.py`, keeping their comments; `CALIBRATION` becomes `'M0.5'`.
- `--provisional` prints the same model with the provisional numbers. It reproduces the §18.1
  ledger: lazy budget 40.1 KB (DESIGN: about 40).

## Deviations from DESIGN.md (and why)

1. **No device numbers.** §4.1, §4.3 and the §18 tables are unchanged; only a status paragraph
   was added to §18.7. The orchestrator deferred the device run and told T1.1/T1.2 to proceed.
2. **`DRAW_EVICTABLE = False` is provisional.** The provisional model says ladder step 4 is
   needed: `integrate S3-S8` (43.9 KB) and `sum` (45.5 KB) fit only with CVDRAW evictable (+7.7
   KB). `definite` (50.5 KB) and `desolve` (51.0 KB) are still about 3 KB short then. CVDRAW stays
   resident, as in §4.1, until a measurement decides. That decision changes `lint.RESIDENT`, the
   manifest row and the UI, and nothing in T1 depends on it.
3. **The model works per line; the DESIGN per module.** §18.2 adds the §4.1 KB column, which
   rounds each module up, so its numbers run 1-3 KB above the model's. One row changes sides:
   `limit` fits in the model (38.9 of 40.1 KB); §18.2 says −1 KB. The test allows this
   borderline row.
4. **`PEAKB` is the worst per-line transient** (the smallest module, if there is a fixed part).
   So `PEAKB × LINES` bounds every part of 100 lines or more. A part under 100 lines may be
   under-counted by up to the fixed part ÷ 100 per line; `FRAG` (3 KB) covers that.
5. **`NMAX`** uses max(`tup4`, `tup5`) as the typical node: 2-6 items share one 32 B block in
   MicroPython. ADD/MUL nodes with 3 or more pairs (`tup7`, 48 B) are rarer.
6. **Probe generator changes from the interrupted first attempt:** prefix-consistent balanced
   blocks (the first version gave PRBL100 a different mix: 18.7 B/line .mpy against 13.6),
   lint-clean generators (no direct `yield g_int(...)` inside `g_int`, see below), re-measured
   `MPY_BYTES` (the old values no longer matched the output), `--provisional`, `--apply`, fits,
   import times, and CRLF-tolerant `stale()`.

- **M0.3 owner:** in `probe/README.md`, point the "Later (not now)" section at
  `probe/README-MEM.md`; fix `test_prbmem_dry_run` as above.
- **M0.1 / T2 integration owner:** the subset lint reports `direct recursion in g_int()` for the
  DESIGN §10.6 pattern `r = yield g_int(t[j], x, depth)`. A yielded generator runs through the
  trampoline and costs no frame, so the rule should exempt `yield g_x(...)` inside a generator,
  or §10.6 should use a helper generator, as the probe template does (`g_int` yields `g_sum`,
  which yields `g_int`).
- **Repo config (optional):** with `core.autocrlf=true`, a fresh checkout writes `probe/*.py`
  with CRLF line ends. MicroPython reads that, and `genprobe --check` and these tests ignore line
  ends. A `.gitattributes` line `probe/*.py text eol=lf` would keep the files byte-identical.
