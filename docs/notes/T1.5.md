Files: `src/parse.py` (the T1.5 part: the builder tables, `tokens`, `expand_names`, `exact`,

## Public API (as implemented)

Levels in brackets.

- **`tokens(text, ctxt=1)` [3]**: stages 3-6 (lex, `ti_rewrite`, `ti_implicit`, then
  `expand_names` unless `ctxt` is 0). `ctxt=0` is the answer path (F4, the round trip).
- **`expand_names(toks)` [5]**: stage 6 (DESIGN 7.6), one work-list loop. Reads `SESS.VARS`,
  `SESS.FUNCS` and `SESS.MACROS` (works with `SESS = None`: only the sum-index rule then).
  1. `sum(`/`riemann(` whose 2nd argument is the bare `i` (or `i=...`): every name `i` in the
     call becomes the first of `k j m` that the call does not use **and that is not stored**.
  2. A stored variable becomes `(` + `lex(text)` + `)`.
  3. `f(a1,...)` with `FUNCS[f] = (params, body text)` becomes `(` body `)`, each parameter
     name token replaced by `(ai)`. The body is `lex`ed only (explicit `*`).
  4. Macros: `MACROS[m] = (min, max, template)`; `#1`..`#9` in the template become `(ai)`. A
     template `None` takes `P.AMAC[m][count - min]`: `arclen` has a 4-argument form
     `integrate(sqrt(1+diff(#1,#2)^2),#2,#3,#4)` and a 5-argument parametric form
     `arclen(x,y,t,a,b)`.
  - Spliced tokens go back on the work list, so names inside them expand. Caps: `MAXEXP = 64`
    expansions, `MAXDEF = 16` nested, both `CasError('definition too deeply nested')`.
  - **Never expanded:** the name right after `=>`, a name right before `:=`, and the
    arguments of `purge(...)`.
  - Spliced tokens carry the source offsets of the name they replace (argument tokens keep
    their own).
- **`exact(v)` [5]**: the id of the rational of the float's 15-significant-digit decimal,
  integer arithmetic only (`frexp`, half-up): `0.25 -> 1/4`, `0.1 -> 1/10`. Subnormals give
  the 15 digits of their binary value.
- **`tcode(s)` [5]**: `rpn(lex(s))`, cached in `K.TCACHE`.
- **`inst(code, env)` [4]**: patterns (`env None`) and templates (`env` a list of `NSLOT` ids).
  - Rule letters (`P.WSLOT`, letter -> `(slot, constraint)`): `U V W` 0-2 ANY, `A B C` 3-5
    FREE, `K` 6 FREE, `M N` 7-8 NUMB, `P` 9 INT, `L` 10 LIN, `Q` 11 QUAD, `R` 12 REST, `x`
    13 (`XSLOT`), **`T` 14 (`TSLOT`)**. `NSLOT = 15`. Constraint codes `P.W_ANY = 0`,
    `W_FREE 1`, `W_NUMB 2`, `W_INT 3`, `W_LIN 4`, `W_QUAD 5`, `W_REST 6`. A pattern letter is
    the leaf `(WILD, slot, constraint)`; `x` is `(WILD, 13, 0)`.
  - Template mode: a letter is `env[slot]`; 0 raises `CasError('rule letter U is unbound')`.
  - Lowercase names: `CONSTS` (`pi e i oo inf infinity undef true false`) or a symbol.
  - Functions: the one-argument ops (`P.ONEARG`), `sqrt`, `exp`, `log`; any other call is
    `CALL(SYM(name), args)`. No angle mode, no commands, no floats.
- **`g_eval(code, ctx)` [2, generator]**: user input (DESIGN 7.8).
  - **`ctx` is a list `[deg, mainvar, approx, inert]`**, indices `P.X_DEG = 0`, `X_MV = 1`,
    `X_APPROX = 2`, `X_INERT = 3`. The same list goes to command generators. g_eval never
    touches `X_MV`.
  - Numbers: `K.num`. A float sets `ctx[X_APPROX]` and is built through `exact()`; in inert
    mode it stays a FLT.
  - Names: `CONSTS`, else a symbol: `theta` is `SYM('theta')` (ASCII; the glyph lexes as
    `theta`), `left mid right trap` are symbols.
  - Operators: `+` `add_`; `-` `add_([a, add_([b], -1)])`; `neg` `add_([a], -1)`; `* / ^`
    `mul_`; `!` `fn_(FACT)`; relations `rel_` (GT/GE through `rel_`). A relation with a
    sentinel operand is `mk((op, a, b))`, unfolded. Arithmetic on a sentinel raises
    `M_RESULT` (through `K.chk`). `'` (not after `y`), `=>` and `:=` raise.
  - Functions: `fnb` [4] (below). `approx(e)` and `evalf(e)` are **builtins**: `approx()` at
    once, flags `F_NOAUTO`.
  - Commands: `nm = SESS.ALIAS.get(f, f)`, `ent = SESS.CMDS[nm]`; arity from `ent[2:4]`;
    `M = SESS.need(ent[0])`, then `x = yield getattr(M, ent[1])(tuple(args), ctx)`. A `None`
    result makes g_eval return `None` (bare `return`): the runner shows the soft-failure
    message. In inert mode every command is `CALL(SYM(nm), args)` (the alias resolved).
  - Unknown calls: `CALL(SYM(name), args)`; `purge(...)` raises `M_PURGE`.
  - Lists: `LST`, including the bare top-level list.
  - **End:** unless inert, if the last RPN item (groups skipped) is a command with
    `F_ALWAYSAUTO`, or is not one with `F_NOAUTO` and `A.simplify_candidate(r)` holds, then
    `M = SESS.need('norm')` and `r = yield M.g_autosimp(r)` (a `None` result keeps `r`).
    Then, if `ctx[X_APPROX]`, `r = approx(r)`. Then `yield r`.
- **`fnb(f, args, deg)` [4]**: the function builders. `log(u) = ln(u)/LN10`,
  `log(u,b) = ln(u)/ln(b)`, `log10` like `log`, `exp`, `sqrt`, `surd(u,n) = u^(1/n)`,
  `O(u) = BIGO(u)`, `asec/acsc/acot(u) = acos/asin/atan(1/u)`, `asinh(u) = ln(u+sqrt(u^2+1))`,
  `acosh(u) = ln(u+sqrt(u^2-1))`, `atanh(u) = ln((1+u)/(1-u))/2`. Wrong counts:
  `CasError('wrong number of arguments')`. Degree mode: trig arguments times `pi/180`
  (distributed over a sum: one `mul_` per term of an ADD, so `sin(x+30)` is
  `sin(pi*x/180+pi/6)`; `2(x+15)` is a product, so it is not distributed), inverse-trig
  results times `180/pi`.
- **`approx(e)` [3]**: giac `evalf`. Every constant subexpression (numbers, `pi`, `e`, and
  ADD/MUL/function nodes of them) becomes a FLT through `A.nprog(x, ())` and
  `A.nrun(prog, ())`. Kept exact: a real NUM exponent of a non-constant base (`x^2`), a NUM or
  `e` base under a non-constant exponent (`2^x`, `e^x`), the coefficients 1 and -1, a zero
  constant term, the sentinels (`DNE DIVG HOLD`, `TRUE FALSE`), `oo`/`undef`, and any
  constant whose evaluation raises (ArithmeticError, ValueError, CasSoft, CasError), such as
  `10^400`. Relations are rebuilt with `rel_`, CALL/LST/BIGO with `mk`. Idempotent.
- **Constants and tables:** `F_NOAUTO = 4`, `F_ALWAYSAUTO = 8`, `F_SOLN = 16` (registry
  flags; bits apart from the token flags 1, 2); messages `M_ARGS M_DEEP M_SYNTAX M_ASSIGN
  M_PRIME M_PURGE`; `ONEARG INVAUX FARGS CONSTS RELOPS WSLOT AMAC`.

## Deviations from DESIGN.md and their reasons

1. **`approx` lives in CVPARSE and `g_eval` applies it** (§6.3 says "the runner applies
   `approx()`"). `g_eval` is the root generator, so the runner gets the final value either way,
   and `approx` must be reachable from `g_eval` (L2) and from the `approx` command. It is L3
   and calls `A.nprog`/`A.nrun` (L4) directly, because `A.nev` is L3 too.
2. **`approx`/`evalf` are builtins of `g_eval`**, not the registry's `('norm', 'g_approx')`:
   numeric evaluation needs only CVALG, so loading the NORM set (24 KB) for it would be waste.
   Both names are in `FNAMES`.
3. **Registry flags are defined in parse** (`P.F_NOAUTO` ...), because parse reads them and
   cannot import run.
4. **The rule letter `T`** (the solve inverse table's slot, §9.3) gets slot 14, so
   `NSLOT = 15`, not 14.
5. **`theta` is `SYM('theta')`**, not the non-ASCII `θ` (SYM names are ASCII, §5.2).
6. **`arclen`**: the registry says 4 to 6 arguments; there are only the 4-argument and the
   5-argument parametric forms (`arclen(x,y,t,a,b)`). 6 arguments give the argument-count
   error. If a 6-argument form is wanted, add its template to `P.AMAC['arclen']`.
7. **Sum index**: the replacement letter also skips stored variables (FlowCE does not), so a
   stored `k` is never expanded into the index.
8. **asinh, acosh, atanh** have no op codes (§5.2), so they are built as logarithms.

## Known gaps / TODOs

- **Size.** CVPARSE is now about **1181 minified lines** (T1.3 alone was 657; the §4.1 budget
  is 440). `bundle.py` fails the line gate for CVPARSE (and CVNODE). The T1.5 part is about
  520 lines: `expand_names` ~120, `approx` ~95, `g_eval` ~95, `inst` ~60, `fnb` ~50,
  `exact` ~30, tables ~50. For T1.15 / §18.8, candidates for a lazy part loaded only when
  needed: `exact` + `approx` (only for float input and `approx`), `expand_names` (only when the
  session has VARS/FUNCS or the line has a macro or `sum(i`), and the T1.3 stages 4-5.
  **Not done here: it needs run's loader tables and a design decision.**
- Arithmetic on lists (`2*[1,2]`) is not distributed (constructors treat LST as an atom).
- `approx` does not descend into `HOLD` (so `approx(factor(360))` stays `2^3*3^2*5`).
- parse now imports alg at module level (`import alg as A`, allowed by the §4.2 order
  `node, alg, parse`), so every importer of parse needs `src/alg.py` (T1.8, present now).

## For downstream tasks

- **T1.6 (run):**
  - Session hook: `P.SESS = R` before any parsing. `R` must have `VARS FUNCS CMDS ALIAS
    MACROS` and `need(key)`; g_eval calls `R.need(ent[0])` for each command and
    `R.need('norm')` for the default result path.
  - `R.start` builds `ctx = [deg, None, 0, inert]`, calls `P.tokens(text, ctxt)` and
    `P.rpn`. The root generator is `P.g_eval(code, ctx)`; its value is already through
    `approx()` (do not apply it again; doing so is harmless, `approx` is idempotent).
  - A `None` from the root means a soft failure (LASTSOFT), as §10.4 says.
  - Use `P.F_NOAUTO`, `P.F_ALWAYSAUTO`, `P.F_SOLN` in `CMDS`.
  - Drop `'approx'` from `CMDS` and `'evalf'` from `ALIAS` (they would preload NORM for
    nothing); `classify` already treats both as FUNCTION.
  - §7.9 rules: detect `purge`, definitions `f(x):=`, `=>` and `name=` **before stage 6**
    (`P.tokens(text, 0)`), then run `P.expand_names` on the expression part only. A function
    body must be stored unexpanded (`P.untok(body_tokens)`), or its parameters would expand as
    stored variables. `expand_names` protects the `=>` target, a name before `:=` and the
    arguments of `purge`, but not a definition body.
  - Builder errors are `CasError(msg)` with one argument (the T1.3 passes add a position).
- **T1.7 (printer):** the round trip is `P.g_eval(P.rpn(P.tokens(text, 0)), [deg, None, 0,
  1])`. FLT text must contain `.` or `E` to re-lex as a FLT (D8): `fdec10(2.0, 15)` is `'2'`,
  which re-parses as the exact 2. `theta` is `SYM('theta')`. Messages for `messages.txt`:
  `wrong number of arguments`, `definition too deeply nested`, `syntax error`,
  `invalid assignment`, `invalid use of '`, `invalid use of purge`.
- **T1.8 (alg):** `approx` calls `A.postorder(e)`, `A.nprog(x, ())` and `A.nrun(prog, ())` on
  constant nodes (V = 0, only NUM/FLT/pi/e/ADD/MUL/function ops) and expects a float or a
  complex. `g_eval` calls `A.simplify_candidate(r)` on any result (LST, relations, sentinels,
  CALL included).
- **T1.9 (rules):** `rset` should build each LHS with `P.inst(P.tcode(lhs), None)` inside a
  region and `K.keep` the pattern ids before putting them in `RULECACHE`: building a pattern
  leaves intermediate nodes that contain WILD leaves, and the invariant scan allows WILD only
  in nodes reachable from `RULECACHE`. Constructors see a WILD as a symbol-free atom (`V = 0`,
  `isreal` False), so they never fold it.
- **T1.10 (norm):** `g_autosimp(e)` is called as a plain generator with one argument.
