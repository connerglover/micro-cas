# M0.2: Shims (notes)

Files: `shim/ti_system.py`, `shim/ti_graphics.py`, `tests/support/keyscript.py`, and the test file
`tests/test_shims.py`. The §21.3 row does not list a test file; it is the only file added outside
the row, and no other task owns it.

All three are desktop-only code. They are not under `src/`, so the device lint, FRAMELINT and the
depth checker do not apply to them, and their frames are free on the "device".

## What was built

### `shim/ti_system.py`: key replay and the cancel poll

- `load(items)` sets a **key script**. `feed(items)` appends to it, `remaining()` returns the
  unread part, and `reset()` clears all state. An item is one of:
  - an int key code (TI-BASIC getKey codes, §16.4), or `ON` (= -1, the [on] key);
  - `after(n, code=CLEAR)`: press `code` at the n-th poll (`escape()`/`get_key()` call) of a
    computation. If it comes directly after a key (only other `after` items in between), it
    binds to that key. Otherwise it binds to the next key.
  - `mark(label)`: when the program next waits for a key, call `MARK_HOOK[0](label)`.
- `wait_key()` returns buffered (type-ahead) keys first, then scripted keys. At the end of the
  script it raises `StopScript`, which is a **BaseException**, so the entry loop's
  `except Exception` and `except KeyboardInterrupt` (§16.2) do not swallow it. A scripted `ON`
  raises KeyboardInterrupt.
- **Cancel model (provisional, PROBE6 settles it):**
  - A press during a computation goes into `BUF`. A [clear] also sets the escape latch.
  - `escape()` returns True once per [clear] and consumes that press.
  - `get_key()` returns the oldest buffered key, or `NOKEY` (= 0) when there is none.
  - One press has exactly one consumer.
  - An `after` press whose poll never comes is dropped at the next `wait_key()` and listed in
    `MISSED`. A fired press is listed in `FIRED` as `(poll, code)`.
  - An `ON` press raises KeyboardInterrupt from the poll at which it fires.
  - `LATCH_CLEAR = True` models a device where a [clear] read by `wait_key` leaves the escape
    latch set. With it, U.2 can test that the UI clears a stale latch before `R.go`.
- Logs: `KEYS_READ`, `POLLS`, `CALLS` (for `disp_*`, `sleep`, `wait` and the lists),
  `OVERRUN`, and `CLOCK` (`sleep`/`wait` never really sleep).
- `disp_wait()` reads keys until it gets a [clear] (the CE documentation). `getKey` is an alias
  of `get_key` [A]. `VERIFIED` lists the 13 EVO names from PROBE2; all of them exist.

### `shim/ti_graphics.py`: draw transcript, framebuffer and screen text

- **Transcript.** Every drawing or state call is appended to `CALLS` as a flat tuple.
  - `setColor` and `setPixel` colors are normalized to `r, g, b`.
  - Queries (`getPixel`, `string_size`, `hsv_to_rgb`) are counted in `COUNTS` but are not
    transcribed.
  - `transcript_text(calls=None)` gives one call per line: ASCII, with strings in `ascii()`
    form. Use it for the `layout/*.txt` goldens.
- **Arguments are checked as MicroPython does.** Coordinates and color channels must be ints, so
  a float raises TypeError. Channels must be in 0..255, and `setFont` rejects unknown ids.
- **Framebuffer.** `FB[y][x]` holds `0xRRGGBB`. `getPixel` reads it, and `pixel()` reads it
  without counting a call. `screenshot(path, scale=2)` writes a PNG, with text drawn as one block
  per character, for agents debugging layout.
- **Screen text.** Each `drawString` becomes an item that owns its cell box.
  - Filled shapes erase the text pixels they cover: `fillRect`, `fillCircle`, `fillPolygon`,
    `fillArc`, `cls`, and the region restored by `popImage`. So does later text.
  - Lines, outlines and pixels never erase text.
  - An item disappears only when all of its pixels are erased. A caret through text keeps it;
    two half-clears remove it.
  - Text drawn over a *different* live text is logged in `OVERDRAW`. Tests should assert that
    `OVERDRAW` is empty. An identical redraw is not logged.
  - Readers: `texts()` returns `(x, y, text, font, (r,g,b))` sorted by y, then x. `texts_in()`,
    `find(sub)` and `screen_text(x, y, w, h)` also read the items.
  - `screen_text` makes lines of text. An item joins a line when it overlaps the line's first
    item vertically by at least half the smaller height, so a superscript stays on its line.
    Items more than 1 px apart are joined with a space.
- `pushImage(x, y, w, h)` and `popImage()` save and restore pixels and text in the region.
  `popImage()` with nothing pushed raises IndexError.
- The **[A] constants** are `W=320`, `H=210`, `FONTS = {0: (8,14,4) big, 1: (6,9,3) small}`
  (font id -> advance, ascent, descent; FlowCE's fixed metrics from §13.3), and
  `TEXT_Y='top'` (the y of `drawString` is the top of the cell). `string_size(s)` returns
  `(adv*len, asc+desc)`.
  - `configure()` changes these constants. `reset()` restores the defaults.
  - `VERIFIED` lists the names in the EVO listing tail. `ASSUMED` lists the names from the CE
    documentation: `cls drawArc drawCircle drawImage drawPolygon`. `assumed_calls()` reports
    any of them that were used.

### `tests/support/keyscript.py`: end-to-end runs

- **Script syntax** (FlowCE `tools/emu/cases` style):
  - Plain text is typed with the §16.4 keys, cut greedily into the longest texts that one key
    inserts. For example `sin(` is the sin key, `pi` is `2nd ^`, `x` is X,T,θ,n, and letters
    are alpha + key.
  - `= != < <= > >= !` are typed through the TEST picker: `2nd math`, then the digit 1-7.
  - `-` is always the minus key, so it triggers the leading-operator rule. `_` types (-).
  - `{name,name}` or `{105}` presses raw keys. The key names are in `KEY`.
  - `{clear@N}` and `{on@N}` inject a press; `{snap}` and `{snap:label}` save a screen
    snapshot.
- **Data and helpers:**
  - `KEYTEXT` is the §16.4 table as data: `code -> (plain, 2nd, alpha)`, with actions written as
    `'@name'`. U.2 can use it as the oracle for its key table.
  - `TYPE` and `type_keys(text, words=True)` turn text into keys. `parse(script)` reads a script.
  - `entry(text)` types a line with a leading `-` as (-), then ENTER.
  - `case(input, keys)` turns a FlowCE case row into keys.
  - `describe(items)` names the keys. `decode(items)` is a reference typist: the round-trip
    property test is `decode(type_keys(s)) == s`.
- **`run(script, program=None, fresh=True, latch_clear=False)`** runs `ENTRY` (`src/casevo.py`).
  - It compiles the source with its real path and runs it with `exec` as `__name__ == 'CASEVO'`,
    so the depth checker sees the entry body as a device frame. The runner adds no device
    frames; `test_run_depths_are_real` checks this.
  - The run ends on `StopScript` (`ended == 'script'`) or when the loop exits (`'quit'`). Any
    other exception propagates.
  - With `fresh=True`, every module under `SRC` (and the program's directory) is taken out of
    `sys.modules` before the run and restored after it. The session imports fresh modules, as
    on the device, and other tests keep the modules they imported.
  - The functions in `AFTER_RUN` are called with each `Session`.
- **`Session` fields:**
  - `mods`, `mod(name)`, and the aliases `s.K`, `s.R`, `s.U`, ... (§4.1 `ALIASES`);
  - `hist` and `ans` (`R.HIST` and `R.ANS`);
  - `screen` (the screen-text dump), `texts`, `calls` (the transcript), `transcript_text(a, b)`
    and `overdraw`;
  - `snaps` and `snap(label)`;
  - `read`, `left`, `fired`, `missed` and `polls`.

## Decisions (not fixed by DESIGN.md)

- `StopScript` derives from BaseException, as explained above.
- One cancel press is consumed once; `NOKEY = 0`. Both are provisional until PROBE6
  (`poll` line).
- `ON` is a pseudo key code (-1): it raises KeyboardInterrupt instead of returning a code.
- Plain-text typing uses function keys (`words=True`). With `words=False`, letters are spelled
  out. Both insert the same text.
- Uppercase letters other than `E` cannot be typed, because alpha-lock behaviour belongs to U.2.
  Use raw keys for them.
- When `shim/` is on `sys.path` and no script is loaded, `wait_key()` raises `StopScript` at
  once. A probe dry run that imports the shims must `load()` keys first. M0.3's
  `test_probes.py` uses its own stubs, so it is unaffected.

## For downstream tasks

- **M0.1 (bug, blocks one of my tests).** In `tests/support/evodepth.py`, `_c_done` returns
  `sys.monitoring.DISABLE` for non-device code. CPython forbids disabling `C_RETURN` and raises
  `ValueError: Cannot disable C_RETURN events. Callback removed.` the first time non-device code
  makes a C call under the checker. The fix is to return `None` there, as device-python §12.2
  does.
  - With that fix (checked with a local patch), `test_run_depths_are_real` passes: entry body 0,
    `go` 1, `work` 2, `leaf` 3.

    is depth 0. `keyscript.run` compiles the entry with its real path, so the two match.

    `tests/test_shims.py` uses an autouse fixture.

## Tests

`tests/test_shims.py` has 55 tests: ti_system replay and injection, ti_graphics transcript,
pixels and screen text, keyscript parsing and typing round trips, and end-to-end runs on a
stand-in entry program with a fake UI module (replay, cancel, [on], quit, isolation, snapshots,
`AFTER_RUN`, depth).

**Status at hand-off:** M0.1's `tests/conftest.py` now runs every test under its checker. With
`evodepth._c_done` as it is, every test in the repository fails with the C_RETURN `ValueError`
(73 of 73, mine included).

With the one-line fix applied as a local in-memory patch, all 55 of my tests pass under the
real conftest: depth checker, post-checks and cleanup. Before conftest existed, 54 of 55 passed
without the patch.
