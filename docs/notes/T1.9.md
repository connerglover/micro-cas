## Public API as implemented

Levels are in brackets.

### `rules.py` (part a)

- **`rset(name)` [3]** returns `{head op: ((pattern id, rhs, guard), ...)}` with the bucket
  `VIEW = -1`, cached in `K.RULECACHE[name]`.
  - The data is the tuple `NAME` (the name in upper case) of the module
    `R.MODS[WHERE.get(name, 'ident')]`. `WHERE = {'itab': 'itab'}`.
  - The data is `(measure, lhs, rhs, guard, ...)` for identity sets and
    `(lhs, rhs, guard, ...)` for tables.
  - An ADD-, MUL- or WILD-headed LHS goes into every bucket. A new head's bucket starts with
    the VIEW rules before it, so every bucket is in file order.
  - The build garbage is dropped with `K.keep(m, None)`, and the patterns are remapped in
    place.
  - An unknown name raises `AttributeError`, so it is loud.
- **`guard_ok(guard, env)` [3]** returns 1, 0, or `(NEAR, op, d)` with `NEAR = 2`. The steps
  follow §9.2:
  1. `inst` builds the guard, and `rel_` may fold it.
  2. The constant difference is evaluated with `nprog`, `nrun` and `ntol`; the T1.8 recipe
     decides it.
  3. Symbols fail the guard.
  4. A non-real value or `Undefined` fails the guard.

  Two extensions are listed under the deviations below.
- **`check(c, s, env, x, trail)` [4]** tests the wildcard constraints, with `c` one of
  `P.W_*`.
  - `FREE` with no focus variable means "constant".
  - `LIN` and `QUAD` bind A, B and C on the trail. They fail when `x` is 0 or when the leading
    coefficient is 0.
- **`g_rewrite(root, rs, x, budget)` [2, generator]**:
  - `rs` is a set name or a compiled dict. `x` is the focus id, or 0/None for none.
  - It runs the §9.7 bottom-up passes: `A.rebuild` on each node, then the first rule of the
    node's bucket.
  - It keeps each pass's result with `K.keep`, yields `TICK` after each pass that changed the
    root, and yields the result at the end.
  - It stops at a fixpoint, at a repeated root, or after `MAXPASS = 8` passes. More than
    `budget` fires in one pass raises `CasSoft('rewrite budget')`.
  - A `NEAR` guard is settled by `R.MODS['norm'].normal(d) == K.ZERO`, and then only for `=`
    and `<=` (`>=` is stored as `<=`).
  - An `Undefined` raised while instantiating a RHS propagates as a soft failure.
- Constants: `VIEW NEAR MAXPASS MAXALT(6) WHERE SA(3)`.

### `rulesb.py` (part b)

- **`match(p, s, env, x, alt=0)` [3]** is the §9.5 matcher: a goal stack, a trail, choice
  points, no recursion, `MAXSTEP = 400`.
  - The AC backtrack is the §9.5 one.
  - A failed match leaves `env` exactly as it was.
  - It reaches `check` as `R.MODS['rules'].check`.
- **`view(op, s)` [4]** views a subject as an ADD or a MUL.

### `ident.py`

- **Identity sets**, each `(measure, lhs, rhs, guard, ...)`:

  | set | contents |
  |---|---|
  | `TAN2SINCOS` | tan, sec, csc and cot to sin and cos |
  | `TRIGSIN` | TAN2SINCOS, then every power of cos of at least 2 through `cos^2 = 1-sin^2` |
  | `TRIGCOS` | the same for sin |
  | `ZBASIS` | an alias of TRIGCOS |
  | `TLIN` | product-to-sum and power reduction |
  | `PYTH` | `N*sin^2+N*cos^2`, and the cosh/sinh, sec/tan and csc/cot pairs |
  | `LNCOLLECT` | `N*ln(U)+M*ln(V)` to `ln(U^N*V^M)` |
  | `LNEXPAND` | `ln(U*R)` and `ln(U^N)` to sums, constants only |
  | `EXPMERGE` | `M^W*N^W` to `(M*N)^W` |

  `rset` takes the lower-case names: `rset('trigsin')`.
- **`denest(e)` [3]** is one-level denesting (alg §2.2): `sqrt(p+q*sqrt(r))^k` with k odd
  becomes `sqrt((p+s)/2) ± sqrt((p-s)/2)` when `p^2-q^2*r = s^2`. The rest of `e` is rebuilt
  unchanged.
- **`lnsplit(e)` [3]** writes `ln(n)` for an integer `n` with two or more prime factors as
  `Σ a·ln(p)`. This is the `ln` step of the zero-test basis (§8.6, step 2).
- **`isq(n)` [7]** is the integer square root.

## Deviations from DESIGN.md, with reasons

1. **The root-only table application is not in CVRULE.** The earlier attempt had a
   `g_apply`. It is removed for two reasons:
   - CVRULE has to fit two parts of at most `LAZYMAX` lines.
   - §10.6 puts the S1 table step in CVINT's `g_table`. CVRULE is loaded for every simplify,
     so the code is cheaper there.

   The loop is about 12 lines; T2.4 can copy `apply1` from `tests/test_rules.py`:

   ```python
   rs = RU.rset('itab')
   for p, rhs, guard in rs.get(K.N[g][0], rs[RU.VIEW]):
       k = 0
       while k < RU.MAXALT and MT.match(p, g, env, x, k):   # env = [0]*P.NSLOT, env[XSLOT]=x
           ok = RU.guard_ok(guard, env)
           if type(ok) is tuple:                            # NEAR: the exact test, at L2
               ok = NO.normal(ok[2]) == K.ZERO and ok[1] in (K.EQ, K.LE)
           if ok:
               yield P.inst(P.tcode(rhs), env)              # then: return
           ...reset env; k += 1
   ```

2. **The part seam moved.** `check` is in part a (`rules.py`); `match` and `view` are in
   part b. §4.3 allows owners to move seams. With the seam as written, CVRULEB was 162
   minified lines, over `LAZYMAX`.
3. **Guards retry bindings (`match(..., alt)`, `MAXALT = 6`).** §9.2 says "guards do not
   backtrack into other bindings". `g_rewrite` now asks the matcher for solution 1, 2 and so
   on (the search order is fixed) when a guard fails or a fire is a no-op. Without this, the
   rewriter fails on two simple inputs:
   - `cos(x)*cos(y)^2` gets stuck: the first binding takes `cos(x)` with `P = 1`.
   - `ln(2)-ln(3)+ln(x)` cannot collect.

   The cost is at most 6 matches per rule and node, each capped by `MAXSTEP`. The default
   `alt=0` keeps the frozen signature `match(p, s, env, x)`.
4. **A no-op fire is not a fire.** When the RHS instance is the node itself (the constructors
   fold it back, as with `ln(2/3)` and `ln(2)-ln(3)`), the next binding or rule is tried, and
   the fire is not counted.
5. **Guard syntax extensions.**
   - A guard may be a comma list of relations, all of which must hold (for example
     `'P>=2,floor(P/2)=P/2'`).
   - A leading `~` lets a difference with free symbols pass. It is meant for branch-policy
     rules (§8.3: the input is real only where the relation holds); constant differences are
     still decided.
   - Only LNCOLLECT uses `~`: `'~U>0,V>0,N^2>=0,M^2>=0'`. §8.3 says lncollect needs no
     guard, but the rule over numbers alone (V = 0) must be exact, and
     `ln(1-pi)+ln(1-pi) != ln((1-pi)^2)`.
6. **Coefficient wildcards (`NUMB`/`INT`).**
   - A NUMB/INT wildcard factor of exponent 1 in a MUL pattern binds the subject's
     coefficient, so `N*sin(U)` matches `-sin(x)` with `N = -1`.
   - A MUL term of an ADD pattern meets a subject term with the subject's coefficient divided
     by the pattern's, so `-N*sinh(U)^2` matches `-2*sinh(x)^2` with `N = 2`.
   - PYTH and LNCOLLECT need this, because canonical sums keep coefficients in the pairs.
   - A repeated `N` must bind the same number.
7. **Changes to the identity sets.**
   - TRIGSIN and TRIGCOS convert a power p in one step: `(1-sin^2)^(p/2)` when p is even,
     `(1-sin^2)^((p-1)/2)*cos` when p is odd. The guards are the parity tests. With the old
     one-step-per-pass rule, `cos^20` needed 10 passes, more than `MAXPASS`.
   - LNEXPAND is new (§9.1 lists it). Its guards must prove positivity, so only constants
     qualify (§8.3).
   - lncollect does not turn a lone `n*ln(u)` into `ln(u^n)`: that form is no smaller and no
     measure decreases.
   - `e^(a+b) -> e^a*e^b` (§8.6) cannot be expressed: the constructors merge it straight back.
     It is not needed, because the canonical form is already merged.
8. **Measures are test-side only.** The device never reads `data[0]`. `tests/test_rules.py`
   defines the kinds `size`, `count`, `excess`, `pow` and `lex`, plus a new kind
   `('split', OP)`: Σ over OP nodes of (the factor count of the argument)². This kind
   certifies LNEXPAND. "Asserted in debug runs" (§9.7) is done by tests only: the property
   test checks a non-increasing measure and soundness after every rewrite of a generated
   input. There is no device-side assertion.
9. **The focus variable `x`.** An identity rule must not mention `x`; the lint checks this.
   With x = 0, the `x` wildcard would act as ANY.

## Known gaps / TODOs

- **TLIN fires one factor pair at a time** and does not expand. `sin(x)^3` gives
  `-sin(x)*(cos(2x)-1)/2`. Full linearization needs `expand` between passes (T1.10).
- **ZBASIS must be applied to an expanded form.**
  - `sin(x)*(sin(x)+1)` hides `sin^2` until it is expanded.
  - Run lnsplit, expand and ZBASIS, then `normal`, and apply ZBASIS to the numerator again if
    needed.
  - "Integer multiples of a common argument" (§8.6) is T2.
- **lncollect** can still leave rational logs apart when every binding of a rule is a no-op.
- **LNEXPAND** does not split `ln(2*sqrt(3))` further: `U` must be a factor of exponent 1.
- **The coverage run (§9.8 test 4)** has a helper, `coverage(corpus)`, and a small built-in
  corpus that warns about rules that never fire. The real corpus run is T1.13's.
- **`MAXSTEP` failures are silent**, as designed.
- An `Undefined` from a RHS aborts the whole rewrite (as a `CasSoft`), not just that rule.
